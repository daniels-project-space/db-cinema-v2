# Private chat scanner

The attachment feature remains disabled until the scanner is provisioned and independently qualified. The upload allowlist is JPG, PNG, WebP, and UTF-8 plain text (`.txt`, up to 1 MB), within a 10 MB overall limit. PDF is explicitly unsupported: every PDF is rejected before scanner storage or antivirus scanning. No PDF parser is installed in this service. Supporting PDF later requires a verified compatible license, a parser with qualified active-content coverage, adversarial fixtures, and resource-limit measurements. Text uploads are downloaded as attachments and never embedded inline. Images retain strict structure and metadata checks. These checks and an antivirus result do not guarantee that files are safe.

The private authenticated `GET /health` endpoint checks that the engine has signatures less than 48 hours old and detects the harmless EICAR test string. It returns no customer data. The checker in `scripts/check-chat-scanner-health.cjs` uses the existing `CHAT_ATTACHMENT_SCANNER_URL` and `CHAT_ATTACHMENT_SCANNER_TOKEN` environment variables; it requires HTTPS, verifies a fresh nonce and fails closed on errors. It does not enable attachments.

The container listens on `0.0.0.0:8787` so a private HTTPS ingress can reach it; local direct runs remain loopback-only unless `CHAT_SCANNER_BIND_HOST` is set to a literal IP address. `EXPOSE` is image metadata and does not publish the port. Do not publish the raw scanner port to the public internet: allow only the private ingress, require TLS at that ingress, and configure the same long random bearer token in Convex and the scanner. The container health check calls the authenticated health endpoint, including its ClamAV signature and EICAR self-check.

The container still requires the deployment to mount a qualified ClamAV Unix socket at `/run/clamav/clamd.sock` and a fresh private tmpfs at `/run/scanner-tmp` owned by UID 1000. The service fails closed when either is missing or misconfigured. No clamd daemon, signature updater, HTTPS ingress, recurring external alert, or production service is provisioned by this repository.

This is a point-in-time diagnostic, not an automated alert or a substitute for signature refresh. Production needs a separately provisioned updater, protected transport, recurring monitoring and operational response before the gate can be considered for release.
