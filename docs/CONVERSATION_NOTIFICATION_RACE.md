# Conversation notification read-marker race

The conversation alert-category separation is locally tested, but is not yet sufficient for release. `postRentalMessage` assigns a logical message time using the greater of the clock and the previous thread time plus one. The owner read marker passes that logical time to `acknowledgeOwnerNotifications`, while notification `createdAt` uses the wall clock. A later message notification can therefore have a wall-clock time below the earlier message's logical read marker and be acknowledged without being read.

The local change resolves message-linked alerts against their original message and compares the message position and creation-time tie breaker. It scans bounded pages and preserves unlinked alerts whose timing is ambiguous. An isolated Convex test exercises the real chat read handler with same-time messages, a logical clock ahead of wall time, more than one batch of newer alerts before older alerts, historical alerts and a subsequent read. Team replies and handler changes use the message they create as the boundary. Synthetic delayed-continuation tests and isolated Convex tests exercise both paths with old and newer alerts; the handler-change test also exposed and verifies a fix for resetting a future logical thread time. This does not establish production behavior; changes remain unpublished.
