# Gaffer chat handoff and alerts

The local rental-chat flow presents the notification invitation after the first visible Gaffer reply, and only when the device's notification state is known and inactive. The choice is stored per account and device. Notification permission and iPhone Home Screen setup still require the renter's own action.

An explicit human request is escalated together with its acknowledgement in one transaction; model-selected handoffs use the same path. Other replies may offer a human in the chat without transferring it. Safety and sensitive financial cases may still require immediate human review. Gaffer-classified completed rental-chat answers schedule a team alert after ten quiet minutes, with stale-conversation checks and a bounded watchdog. This is an AI classification, not independent proof of customer satisfaction.

For the storefront account-support widget, `/api/bot` reads the authenticated stored conversation rather than trusting the browser's history. It signs a short-lived assertion only when the model classifies the answer as complete and the deterministic checks find no outstanding question, human handoff, missing rental window or unconfirmed item. The assertion binds the stored renter message and exact answer; Convex verifies it before scheduling the same ten-minute alert. The browser can still save a reply without a valid assertion, but that reply cannot trigger an alert. Set the same strong, randomly generated `GAFFER_COMPLETION_PROOF_SECRET` in the Vercel and Convex environments before enabling the integration; absent or mismatched secrets fail closed. Rotate both together, and never expose this secret to the browser. The classifier is an estimate, not proof of customer satisfaction. Explicit human requests still escalate immediately. Provider delivery can retry and cannot be guaranteed exactly once. These changes are local and have not been verified on production or with actual phone permissions.
