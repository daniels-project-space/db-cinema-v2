## Late rental time

The booking saves each item's daily rate at checkout. At physical return, the admin records the actual return time. The server calculates each commenced London-local rental day after the agreed return slot. It sends an itemised notice, allows seven days to dispute, and attempts collection no later than 30 days after return. It captures an unused active hold only when no damage deduction was made, then charges only the remaining amount on the saved card. An issuer can decline or ask for customer authentication.

When that separate saved-card PaymentIntent needs bank authentication, the customer receives an account link and can approve the **remaining late charge** in their rental account. The server checks booking ownership before releasing Stripe's client secret. It then retrieves the same PaymentIntent to record the actual amount paid and send an updated receipt; the hourly job also reconciles it if the browser closes. An unapproved action is cancelled after the 30-day window, without attempting a new charge. Expired account sessions cannot access this approval flow.

Automatic financial collection remains off unless `LATE_FEE_AUTOCOLLECT_ENABLED=true` is deliberately set on Convex after the legal and provider review. A disputed fee can be paused in the admin booking row; this releases an unused hold. The 50% refundable payment is refunded on safe return, and an uncaptured hold is cancelled when there is no late fee. The admin must record evidence before retaining a damage amount.

## Return and receipt

The admin **Return** form records the physical return time and shows the calculated per-item late amount. It can apply or waive that charge, record an evidenced damage/loss deduction, or do both. Damage uses the active hold first and then the refundable security payment. A late charge stays a separate assessment with its own itemised notice, seven-day dispute period and collection attempt; an unused hold is eligible only when no damage was retained. The return decision is saved before Stripe settlement so the same amounts can be resumed safely if a provider call fails. The return statement is generated from a saved snapshot after the refund/capture; email with the non-VAT PDF is retried hourly on delivery failure. A later late-charge outcome sends a separate paid/unpaid breakdown email.

The original checkout receipt and return statement are **not VAT invoices**. UK invoice guidance requires the real supplier name and address on a customer invoice; do not activate automatic financial documents until those values are configured. [GOV.UK invoice particulars](https://www.gov.uk/invoicing-and-taking-payment-from-customers/invoices-what-they-must-include).
