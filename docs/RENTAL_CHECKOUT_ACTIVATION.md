# Rental checkout activation

This branch changes direct bookings only. The 50% refundable security payment and the full separate card hold are calculated from the existing protection category. A later late-time fee is a separately agreed obligation. It can use an unused active hold after notice; any remainder is a new saved-card transaction. The code deducts the hold capture from the amount attempted on the card.

As checked on 30 September 2026, the development Convex deployment has the rental Stripe test payment configuration but no Sumsub credentials, Stripe webhook signing secret, or late-fee collection flag. The local frontend has no Stripe publishable key. New direct checkouts deliberately stop at the activation/provider preflight until these are configured. No live Stripe or Vercel deployment was changed.

A guest renter must create an account using the booking email to approve a later challenge.

## Late rental time

The booking saves each item's daily rate at checkout. At physical return, the admin records the actual return time. The server calculates each commenced London-local rental day after the agreed return slot. It sends an itemised notice, allows seven days to dispute, and attempts collection no later than 30 days after return. It captures an unused active hold only when no damage deduction was made, then charges only the remaining amount on the saved card. An issuer can decline or ask for customer authentication.

Automatic financial collection remains off unless `LATE_FEE_AUTOCOLLECT_ENABLED=true` is deliberately set on Convex after the legal and provider review. A disputed fee can be paused in the admin booking row; this releases an unused hold. The 50% refundable payment is refunded on safe return, and an uncaptured hold is cancelled when there is no late fee. The admin must record evidence before retaining a damage amount.

## Return and receipt

The admin **Return** form records the physical return time and shows the calculated per-item late amount. It can apply or waive that charge, record an evidenced damage/loss deduction, or do both. Damage uses the active hold first and then the refundable security payment. A late charge stays a separate assessment with its own itemised notice, seven-day dispute period and collection attempt; an unused hold is eligible only when no damage was retained. The return decision is saved before Stripe settlement so the same amounts can be resumed safely if a provider call fails. The return statement is generated from a saved snapshot after the refund/capture; email with the non-VAT PDF is retried hourly on delivery failure. A later late-charge outcome sends a separate paid/unpaid breakdown email.

The original checkout receipt and return statement are **not VAT invoices**. UK invoice guidance requires the real supplier name and address on a customer invoice; do not activate automatic financial documents until those values are configured. [GOV.UK invoice particulars](https://www.gov.uk/invoicing-and-taking-payment-from-customers/invoices-what-they-must-include).

- Complete Stripe test checkout for both protection categories; confirm the amount charged is half the category amount, the separate hold equals the full category amount, and the card appears only once in checkout.
- Exercise hold success, issuer challenge, decline, expiry, return, damage capture, cancellation, refund, and a renter closing the success page before webhook delivery.
- Exercise hourly renewal with a short-lived test hold, issuer challenge in the renter account, decline, old-hold cancellation, and a renter who never responds. Check that the admin sees a failed or pending renewal before handover.
- Exercise late return notice, dispute pause, hold-funded fee, fee larger than hold, saved-card decline, and 30-day expiry. Reconcile Stripe receipts to booking amounts.
- Exercise an admin damage deduction notice, a requested deduction larger than the live hold, and admin/customer cancellation while Stripe Checkout is still open or newly paid.
- Exercise safe return, damage only, late only, both damage and late, waived late time, a failed refund followed by saved-decision retry, emailed itemised PDF, PDF failure/retry, and later separate late-charge result email. Check pence values and that no VAT appears.
- Verify the exact production Vercel alias and production Convex deployment independently. No successful build or dev deployment proves the live site is updated.

Apple Pay merchant-initiated reuse requires an appropriate merchant token flow through a different Payment Element integration. The current hosted rental Checkout intentionally excludes wallets until that is built and tested. This payment path cannot guarantee later charges or indefinite card holds.
