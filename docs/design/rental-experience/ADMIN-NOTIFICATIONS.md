# Admin notification settings

The admin Settings page now opens with a dedicated notification panel. It shows whether push credentials are configured, explains phone/Home Screen setup, and provides actual team-device controls: saved names, separate requests-to-speak-with-the-team and renter-reply preferences, save and remote disable. These match the two existing owner notification event kinds; no unused booking-alert switch is presented. Device preferences affect queue creation and claim-time delivery, while the in-app attention records remain available regardless of phone preferences.

The protected settings query returns the 50 newest device records (with an explicit truncation message) and 30 newest delivery records. It excludes subscription URLs, encryption keys and customer message bodies. Delivery rows show the saved device name, actual status, attempts, updated time and sanitized failure. "Sent" means provider acceptance, not that a person saw it. An eligible failed delivery can be retried through an audited admin mutation: the subscription generation must still match, the device/type must be enabled, the notification must remain unread and younger than 24 hours, and the row must actually be retryable. Concurrent/repeated clicks cannot requeue an already queued/delivering/sent record. Retries clear the old claim and use the existing durable transport and fenced outcome path.

New owner deliveries retain the subscription version at queue time. A replaced/disabled device cannot receive an older queued delivery. Legacy queued rows without that version are skipped rather than reassigned to an unverifiable current endpoint; their original in-app attention entries are retained. Subscription/disable/expiry versions advance monotonically. Registering the same endpoint under a replacement browser device ID disables older enabled duplicates, preventing double alerts after local-storage reset. Active claims move their due timestamp forward to the lease recovery time, and a two-minute cron recovers due queued/retry/killed-worker records. A missing subscription during an expired outcome is handled safely.

The owner bell now prepares its admin-scoped worker before the tap, starts subscription from the tap, handles denied permission and missing browser subscriptions, and distinguishes a browser connection from a saved backend row. The admin-only layout links an admin-only manifest that opens `/admin`, separate from the renter app's `/account` manifest. iPhone/iPad setup requires opening the Home Screen app first. No public-page/global styling, customer payment logic, gates or production credentials changed.
