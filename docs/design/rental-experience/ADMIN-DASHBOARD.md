# Operational admin dashboard

The admin overview now leads with actual rental operations in the existing dark management shell: active/confirmed rental counts, unread messages, recent alerts, current kit cards, collection/delivery handovers and working rental/calendar/inbox/report navigation. The protected analytics query remains the data source. Traffic and demand statistics remain available in Reports.

An active rental stays visible until its return is recorded, including equipment overdue by weeks. A confirmed rental is awaiting handover and does not claim equipment has been collected. The previous ±1-day date filter mixed these states and hid long-overdue active rentals. Counts cover the complete indexed active/confirmed query results; each overview group shows six cards with a complete-count link to the existing paginated rental view. Cancelled/returned rentals are excluded from these operational groups.

Cards retain actual customer identity, kit quantities and independent date periods. Photos use current public listing sources and their real fallbacks, with one cached listing read per unique ID for the visible cards. These are existing catalog photographs; the goal's faithful ERNIE equipment images still need acceptance and binding. Unknown dates/times are labelled for review rather than invented. The latest agreed return slot follows the last equipment period and per-line overrides, preserving an explicitly unagreed time. Overdue labels use the existing London-time calculation against each agreed line deadline; this query calculates display state only and executes no fees or financial writes.

All queries remain admin-authorised. Private verification identifiers, billing addresses and provider secrets are not projected into the dashboard. An older summary response produces an honest unavailable state with working rental navigation instead of a crash or invented zero counts. CSS is local to the new admin component; public checkout, gear and landing page layouts are untouched.
