# Permanent ownership in the renter account feed

The paginated account feed previously started from the guest-email index. A rental with an immutable account ID but its original booking email vanished after that account changed its email. The non-paginated helper and protected invoices already recognised account IDs; the account's paginated screen did not.

The feed now merges two indexed streams, ordered by creation time and document ID: all rentals permanently linked to the signed-in account, and unlinked legacy rentals at its current email address. The new `by_account_guestEmail` index keeps the latter lookup restricted to unlinked records. A matching email cannot grant access to a rental already linked to another account. Cursor values never replace the account's ownership predicates.

`convex-helpers` is pinned to 0.1.120, which declares compatibility with the current Convex SDK. The client uses that package's actual reactive pagination hook so previous page end cursors stay bounded when new rentals arrive. Convex's official [query-stream documentation](https://github.com/get-convex/convex-helpers/blob/main/packages/convex-helpers/README.md#composable-querystreams) explains why that client/server pairing matters. Page requests cap at 50 results and 100 rows of indexed stream scanning; invalid sizes are rejected. No all-bookings collection or email backfill is introduced.

Validation invokes the actual stream library and actual account query over 137 synthetic mixed permanent/legacy rentals. It covers repeated creation timestamps, no duplicates or omissions, old-mailbox reuse, bounded indexed reads, growth of a bound first page after an arrival, unchanged next-page boundaries, foreign cursor isolation and invalid page sizes. The complete existing tests and production build pass. Native fixture `/tmp/dbc-account-pagination-fixture` uses the actual reactive helper hook, account handler and booking components, with isolated transport and storage. It loads all 137 records, checks end-cursor propagation, switches to the old-mailbox owner and verifies desktop/mobile overflow. Screenshots in `/root/dbc-account-pagination-review` are synthetic evidence, not deployed account acceptance.

Release requires deploying the index and query together with the matching account client. Hosted signed-in data and document access still need verification, alongside the broader goal's private Rental Manager pairing, document archive and financial acceptance.
