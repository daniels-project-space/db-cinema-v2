# Protected invoice history and dark document workspace

Admin invoices previously reused the newest 100 rental records. Older paid receipts and issued return settlements disappeared from the library even though their private PDF endpoints still existed. The new adminInvoicePage query pages the complete rental history in bounded batches and sends a compact document-list projection. Verification results, agreement copies, Stripe IDs, damage notes and execution fields remain outside the list. The admin wrapper loads ten records at a time and exposes older-page access; search/counts explicitly describe loaded records.

The admin page uses a separate database-free authorization query. At source 20ee721 its legacy 100-record booking query ran only for the calendar, avoiding a redundant wide rental read on invoices. The subsequent calendar-history change removes that remaining consumer and is documented separately in CALENDAR-HISTORY.md.

The dark invoice layout follows the saved design's compact invoice/rental/customer/date/amount/status columns and selected-document panel, with copper selection and existing protected PDF actions. Multiple independent rental periods stay distinct rather than being shown as one continuous hire. Return rows use their saved settlement issue date; absent dates are shown as not recorded. Renter history receives the same saved date. Rental status is labelled as such; released authorisations, actual cash refunds and issued account credit remain separate. Reference mock VAT/damage-waiver figures are not copied into live billing.

PDF viewing is scoped to the admin/account session epoch. Selecting another document, closing details or the preview, or changing the session cancels pending viewing. A delayed old response cannot revive its preview after A/B/A navigation. Blob URLs are revoked on close/unmount/session changes. API authorization and private PDF generation remain unchanged.

Validation: actual protected handlers page all 143 synthetic records in stable order without duplicate IDs, reaching the oldest record beyond the previous cap; deny access before database reads; enforce page/read bounds; omit private payloads and project saved settlement dates. Native production ManagementShell/AdminInvoiceLibrary/InvoiceLibrary plus actual protected handlers exercise older-page access/search, correct selected customer, cancellation of delayed PDF downloads, private URL revocation and session A/B/A isolation. Pagination/download transport is controlled and the PDF is an actual generated synthetic statement fixture; no live provider/account/financial write or real customer PDF acceptance is claimed.
