# Shared stock constraints at the full cart

The prior complete-kit importer still read only DB Cinema upstream bookings. Through the actual authenticated HTTP route, it offered a complete kit when its shared lenses were booked on another account, held for repair, blocked by the owner, or unavailable during a vacation. Each of those independently blocks the corrected importer against the same controlled source.

Rental Manager now provides one private shared-stock snapshot using its existing loadStockSources and stockOccupancyForItem calculation. The manager's own quotes use that same occupancy helper. The snapshot includes confirmed/ongoing bookings on all shared accounts, audited kit allocation, default adapters, overdue custody, extension grouping, repairs, master-specific owner blocks and active vacations. Website booking copies are excluded because their actual reservations already occupy the local website ledger. No renter, account, order, message, case or private reason is exported.

The website's existing 15-minute sync action now requires the versioned shared snapshot. One mutation validates the whole batch, resolves physical identities, replaces upstream windows and updates exact current capacity. Deleted masters supply zero capacity. Unknown source components are not invented; duplicate local physical identities reject for reconciliation. Local site/subscription rows, catalogue mappings, owner tags and photos are preserved. Matching source replay changes nothing; older or conflicting parallel receipts reject without freeing occupied stock.

After shared stock is established, a slower catalogue response cannot overwrite physical capacity or reactivate retired stock. Newly mapped pools start at zero until a shared receipt verifies them. The same cached receipt can repair newly mapped pools or incomplete local occupancy; a genuinely intact replay leaves reservations untouched. The unused legacy primary-only mirror mutation is removed after verifying it has no real caller.

Shared windows are sparse, disjoint and half-open. Same-kit extensions use their maximum quantity; independent rentals add together. A midnight release frees the following day, while the manager's return buffer crossing midnight blocks it. The website's existing rental-day allocations stay inclusive. Full-cart, listing, replacement and checkout-hold checks use the same interval clipping and peak calculation.

These stock coordinates encode the manager's London date/time labels against full-day cart requests. They are not new calendar or pickup timestamps. Calendar/logistics still use the original saved booking and per-item window data. This change does not claim finer pickup-time booking controls or alter the public catalogue/landing appearance.

Validation: actual manager source/HTTP checks compare the exported peak with real quoting, cover all constraints, exclude website copies/private metadata and preserve return buffers. Actual website import/cart/replacement/hold tests cover atomicity, capacity changes/deletion, exact replay, stale conflicts, sparse peaks and day boundaries. Native paired real HTTP/client handlers confirm each constraint blocks and actual clearance restores the kit; a separately loaded prior actual importer reproduces the gap.
