# Unresolved amendment reservations survive timer expiry

The actual stock reader ignored expired extension/addition holds whenever their parent rental was already confirmed or active. The independent timer cleanup also deleted those holds. The original pending-checkout guard did not cover an approved extension awaiting payment, an interrupted addition payment or an unresolved extension refund. A competing basket could therefore acquire stock before the payment reconciler attested closure.

One shared reservationPaymentUnresolved decision now protects both availability occupancy and timer deletion. Existing pending checkout protection remains. Extension rows are tied to their own change request and booking; item additions use their existing addition reference. Nonterminal and unknown states preserve stock, as do missing/mismatched amendment bindings requiring reconciliation. Actual terminal applied/refunded/expired/withdrawn/declined states allow residual expired hold cleanup according to each operation's existing state contract. Future holds, original confirmed/active allocations and planned dates are unchanged. This moves no payment, refunds no money and sends no message.

Actual occupancy/feed/full-cart/replacement/transactional-hold tests verify that each unresolved extension/addition state and unknown/mismatched bindings remain unavailable and survive cleanup, while properly terminal operations release residual expired rows. The real owner-approved extension/payment handler fixture also checks its actual expired hold before payment, during refund_pending, and before successful settlement. A prior-source control loads actual 161f683 stock-reader and timer functions: the prior reader ignores the unresolved extension and its timer deletes it; the current functions retain it. Fixtures use synthetic database and controlled provider responses, with no external writes.
