# Renter rental cards

The account rental groups now give their first non-history rental a larger equipment showcase beside the real booking title, dates, logistics, progress and security summary. The primary source photo uses the existing image fallback chain; additional unique kit photos appear as thumbnails without repeating pictures for repeated units. Kit quantities, separate periods and prices remain available in the full contents list. Later cards and history retain the compact presentation.

The visible progress uses actual saved payment, card-hold, verification and rental states. Account enrichment now includes the current kit's drone requirement, including drones nested in packages, and its saved manual licence decision. Document approval alone cannot make a drone card point to pickup while licence upload, replacement or review is still required. Private licence storage IDs are excluded from this account projection. A larger card uses a single labelled progress list plus the existing verification-page link.

Refundable deposit and card authorisation are separate amounts; the latter is explicitly labelled as not a payment. No financial execution or approval rule changed. Chat, cancellation options, unpaid draft removal, receipt/return-statement downloads, calendar export, additions, late fees and hold approval still use their existing scoped callers.

Validation: the full `npm test` suite and final Next production build pass. `test-renter-progress.cjs` invokes the real account projection and presentation helper for direct/nested drones, private-file exclusion, unpaid/hold/document priorities, manual review/replacement/approval and returned/cancelled rentals. The native browser fixture at `/tmp/dbc-renter-showcase-fixture` uses actual components and the actual account query with synthetic records and isolated transports. It checks current/history/payment groups, visible real amounts, chat routes, authenticated receipt/calendar URLs, unpaid cancellation caller and error feedback, mobile navigation and overflow. Screenshots are in `/root/dbc-renter-showcase-review`.

The screenshot fixture deliberately exercises missing source photos, rather than substituting invented equipment images. It does not prove actual customer-photo delivery, live document access, live payment execution or production deployment. Full reference fidelity, accurate equipment assets, hosted account acceptance and the paired backend/frontend publication remain open.
