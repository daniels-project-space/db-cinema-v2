# Complete calendar history and actual line periods

The admin calendar previously received only the newest 100 bookings and marked every day between a booking's earliest start and latest end. Older rentals disappeared; separate hires of one item painted a false continuous interval. Its 400-day iteration guard also dropped later portions of long hires. Selection showed all kit and global pickup/return times on every occupied day.

The actual admin calendar now consumes a protected compact paginated query in bounded 50-record/read batches and continues until history is exhausted. It shows the loaded-record count while checking; a selected empty date cannot claim no rentals before completion. The old wide adminList query is removed from the admin page. Session changes remount the scoped wrapper. This scans history on calendar opening; the compact response and bounded requests avoid one unbounded response, but do not claim a date-indexed database read or constant total cost for arbitrarily large histories. Renter calendar navigation also continues its existing protected ownership-aware pages while that tab is active; other renter history surfaces retain their load-older controls.

The shared calendar projects actual per-line London civil dates into only the displayed month. Disjoint periods preserve their gaps; overlapping lines create one rental entry per day with exactly the present item quantities. A collection time appears on a line's first day, and return rows appear on its last day with its saved individual return time or the saved booking fallback. Missing times are explicitly unrecorded. Renter booking projections now preserve individual return times. No booking is amended, reservation released or occupancy source changed by this presentation update. The schedule is planned rental dates; ongoing custody/overdue stock remains separately occupied by the existing stock authority.

Validation uses the actual protected calendar handler and actual month projection: stable 143-record complete history beyond the old cap, authorization before database reads, page bounds and no private financial/verification/contact payload; disjoint gaps, overlaps, exact quantities/times, long hires past 400 days, month clipping, leap day and London DST. Native actual AdminRentalCalendar/RentalCalendar/ManagementShell plus actual handlers exercise automatic paging, incomplete-empty-day text, oldest booking selection, collection and return boundaries, line-specific return times, month navigation, denied session and mobile overflow. Database and pagination transport are controlled; no real customer/provider writes or live backend acceptance is claimed.
