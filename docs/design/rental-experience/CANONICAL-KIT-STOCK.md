# Complete-kit inventory contract

A primary-camera match does not certify a rentable kit. The previous actual website importer advertised four kits for a controlled source with four bodies, three lenses and twelve batteries, despite the audited kit requiring two bodies, two lenses and five batteries. The actual source components support one kit.

Rental Manager now exports a single authenticated catalogue snapshot containing the real listing resolver's ownership, description coverage, audited override and stock-required component quantities. Physical capacity comes from each eligible master record, including zero, inactive and marketing stock. Standard accessories that the manager intentionally does not track are not invented as stock constraints.

The website requires this contract, imports every required component into a shared master pool, and checks all components through its existing cart, replacement and hold handlers. Older primary-only payloads reject before writes. Conflicting shared records, duplicate components and malformed counts reject the complete batch. A new fingerprint namespace reapplies old snapshots. Incomplete or explicitly unowned mappings keep cards selectable for demand logging but cannot be promised at checkout; they do not change the owner's marketing-only choice.

Upstream occupancy is exported using the manager's actual reservationItemUnits calculation. Audited kit overrides supersede stale primary-only guesses, including tracked accessories and default adapters. An explicit empty physical allocation remains empty; the website does not fall back to an old guess. Invalid canonical reservation counts reject before mirror writes.

Images and existing rental allocations remain unchanged. A changed component mapping clears the stale catalogue packing list. Preserving past allocations is not a safe stock migration: before live rollout, review and reconcile all active website allocations created under primary-only or product-specific pools. Recover historical components from the original booking evidence; do not silently apply a newly configured kit to an old rental. Resolve mapping conflicts and incomplete source records before promising their stock.

Local evidence: actual client/server tests, full default suites and builds; manager 140 files / 2152 passing tests / 14 skips and both owner audits. The native paired HTTP fixture invokes the real registered authenticated route, source resolver, website importer, reservation mirror and cart query with controlled data. It verifies one complete kit, shared body stock, exact upstream 2/2/5 occupancy, empty overrides and rejected credentials preserving existing stock. The prior actual importer reproduces four nominal kits against the same source. These are synthetic inventory fixtures, not deployed source-to-cart acceptance.
