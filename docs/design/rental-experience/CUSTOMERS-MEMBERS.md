# Customers & Members implementation

The account directory and profile panel now follow the approved dark customers concept. The profile includes membership/access status, usable credit, recent rentals, conversations, retained-document summaries, internal notes, and the existing audited access/blocking controls. Profile tabs expose the full retained documents and recent account history. Rental and conversation buttons navigate the actual admin workspaces with the selected account/booking IDs. Small screens stack the panels; selecting a row reveals the profile and keeps verification status visible.

All values come from existing account/booking/chat/credit/archive records. The new `accountAdmin.detail` query requires admin authentication and returns a deliberate projection without password hashes, payment-provider identifiers or raw document URLs. Permanent account booking IDs take precedence over legacy email linking. Conversation booking ownership is checked independently of the recent-rental limit. Available credit uses the same per-source reservation and revoked-credit logic as checkout. Notes require an admin mutation, a real account and non-empty bounded text; they are stored under that account and cannot appear on another profile.

The directory now uses server-backed cursors across every account, with case-insensitive name/email substring search and canonical membership/verification filters. Each query reads at most 100 accounts and returns only matching safe summaries. The browser automatically continues through sparse or empty batches until it has the requested ten-row page plus lookahead, or reaches the end. An older customer is reachable without knowing an exact email. Counts say “loaded” until the real end is known; they do not pretend a partial directory is the total. A changed query or expired admin access clears the selected profile while loading. Customer grants are distinguished from paid billing; access changes do not create paid subscriptions or mint credits.

This deliberately uses bounded scans rather than a new denormalised search field that would require backfilling every account and synchronising every account writer. Rare searches can read the full directory over multiple small queries; no nonmatching private profiles or document bytes are sent to the browser.
